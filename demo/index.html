4. Infinite scroll (vertical, variable row height)

Starts with a small page of rows and fetches (simulated) more from a "server" as soon as the buffered range gets close to the end of the currently loaded data - i.e. before the user actually scrolls to the bottom. New pages are appended via appendData(), so the scroll position is never reset. Row heights vary per item.

5. Infinite scroll (horizontal, variable column width)

Same idea as demo 4, but along the column axis: appendData() grows the columns (not the rows) when orientation="horizontal", since the column axis is what carries the items for a horizontal list. Column widths vary per item and are auto-measured, same as demo 3.

6. Sliding window / infinite scroll (vertical, memory-capped)

Combines infinite loading with a hard cap: once a new page is appended via appendData(), if the loaded row count exceeds the cap, the oldest rows are pruned from the top via removeDataFromHead(). The viewport is counter-scrolled by the exact removed pixel height in the same frame, so scrolling stays perfectly smooth even though the array (and the WASM vectors backing it) never grows past the cap - memory usage stays flat forever, no matter how far down the user scrolls.

7. Sliding window / infinite scroll (horizontal, memory-capped)

Same idea as demo 6, but along the column axis: once a new page is appended via appendData(), columns beyond the cap are pruned from the left via removeDataFromHead(), which counter-scrolls the horizontal axis so nothing jumps. The columnsData array (and the WASM column vectors) never grows past the cap, keeping memory flat during infinite horizontal scrolling.
