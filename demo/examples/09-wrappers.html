Framework Wrappers

runway-grid is a framework-agnostic Web Component — it works in any environment that supports Custom Elements, without needing a framework-specific wrapper.

Community-maintained wrappers provide a more idiomatic integration experience for specific frameworks. If you build one and publish it, we'd love to feature it here — just open a GitHub Issue with the details.

Building Your Own Wrapper

Since runway-grid is a standard Custom Element, wrapping it for any framework is straightforward. The core API consists of:

  • Attributes: orientation, row-size, col-size, buffer-size, momentum-friction, momentum-max-speed, wheel-speed
  • Properties: data, columns, template
  • Methods: scrollToCell(), scrollToIndex(), appendData(), removeDataFromHead(), startAutoScroll(), stopAutoScroll()
  • Events: rangechange, wasmerror

For detailed API documentation, see the main demo page. For framework-specific integration patterns, check the reference demos above.

Attribution Requirement

Any community wrapper must prominently credit runway-grid as the underlying library. Specifically, the wrapper's README.md (or equivalent documentation) should include a clear link back to the original runway-grid repository and mention that it is built on top of runway-grid. This ensures proper attribution regardless of how popular the wrapper becomes.

See CONTRIBUTING.md for the full framework wrappers policy.
